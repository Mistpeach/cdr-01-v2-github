# CDR01 v2 固件烧录与排障

## 1. 硬件

- ESP32-S3 N16R8（16MB Flash QIO + 8MB OPI PSRAM）。
- 6×SG90：L0-L2 = GPIO 4/5/15，R0-R2 = GPIO 16/17/18。
- 舵机电源接外部 5V，与开发板**共地**，不要从开发板 5V 取电。
- ⚠️ GPIO15/16 是 ESP32-S3 的 32K 晶振脚：确认板背**没有** 32kHz 圆柱晶振（有则换脚，改 `config.h`）。

## 2. 烧录（PlatformIO）

```bash
cd cdr-01v2/firmware
pio run -t upload     # 首次需下载 espressif32@6.9.0 工具链
pio device monitor    # 115200 看日志
```

- 板型已按 N16R8 配置；若实为 N8R8（四线 PSRAM），`platformio.ini` 改
  `board_build.arduino.memory_type = qio_qspi`、`board_build.psram_type = qspi`。
- 国内下载慢：给 `pio run` 设代理环境变量 `HTTP_PROXY`/`HTTPS_PROXY`（见 v1 手册经验）。

### 3.1 串口到底在哪个 COM 口？（重要）

ESP32-S3 板子常见有两个"串口"来源，选错就会出现"只看到 ROM 启动信息和红色 `[E]` 日志、看不到自己的打印"：

| 来源 | 典型内容 | 说明 |
| --- | --- | --- |
| **USB CDC（Arduino `Serial`）** | `[BOOT] ...`、`Setup complete`、命令响应 | 固件已切到 **USB-OTG (TinyUSB)**，与 Arduino IDE "ESP32S3 Dev Module + USB CDC On Boot" 的默认一致；通常是**新出现的那个 COM 口** |
| UART0（GPIO43/44 或 USB-Serial/JTAG 控制台） | ROM 启动信息、ESP-IDF `[E]` 日志、`nvs_open` 等 | 与固件 `Serial` 不是同一个口 |

固件已做**双口镜像**：`[BOOT]`、自检、命令响应会同时写到 USB CDC 和 UART0，所以：

- 若你插上板子后看到**两个新 COM 口**，分别打开试，能看到 `[BOOT] CDR01v2 ...` 的那个就是正确的；
- 若只有一个口，且能看到 `[BOOT]`，就直接用它；
- 还看不到时，用 `pio device list` 或设备管理器确认端口，并注意**不要**只盯着显示 ROM 启动日志的那个口。

烧录本身不依赖以上选择（esptool 走 ROM 下载模式）。

## 4. BLE 帧验证（nRF Connect 手写 hex，无需上位机）

向 CMD 特征写入以下十六进制帧（Write / Write Without Response 均可）：

| 动作 | 帧 hex |
| --- | --- |
| 双侧 STOP | `CD 01 00 04 00 53 54 4F 50 81 DC` |
| 左侧 POINT 0 0 0 300 | `CD 01 01 0F 00 50 4F 49 4E 54 20 30 20 30 20 30 20 33 30 30 94 43` |
| 右侧 REPEAT_LINE | `CD 01 02 22 00 52 45 50 45 41 54 5F 4C 49 4E 45 20 2D 35 30 20 30 20 2D 32 35 20 35 30 20 30 20 2D 32 35 20 37 30 30 30 11` |

- 写入后 EVT 特征应收到 `[L] OK ...` / `[R] OK ...` 通知；每秒收到一条 `HB` 心跳帧 `CD 01 02 02 00 48 42 04 54`。
- 故意写错 CRC（改帧尾一字节）→ EVT 回 `ERR CRC`。

## 5. 排障表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 串口无输出 | CDC 未开 / 线坏 / 波特率错 | 115200；CDC On Boot；换线；长按 BOOT 重烧 |
| **只看到 ROM 启动/红色 `[E]` 日志，看不到 `[BOOT]`/`Setup complete`** | 监控的是 UART0/控制台口，不是 USB CDC | 见 §3.1：换另一个 COM 口；固件已双口镜像，正常应有 `[BOOT]` 横幅 |
| BLE 扫不到 `CDR01v2` | 烧的是 v1 / 广播未起 | 确认串口有 `BLE advertising started (CDR01v2)`；重新烧 v2 |
| 上位机连上但无响应 | 帧 CRC 错 / 命令无效 | 看串口 `Received Command` 与 `ERR ...` |
| 舵机不动 | 信号接错 / 没共地 / 没电 | 量舵机端 5V；确认共地；查 GPIO 表 |
| 舵机乱抖 | **未共地**（最常见）/ 电源不足 | 先查共地；换 3A+ 电源；缩短信号线 |
| 某臂方向反 | 该通道装配镜像 | `config.h` 的 `SERVO_INVERT` 对应位改 true |
| 动作剧烈复位 | 5Vin 压降 / 电源不足 | 开发板改母线直供；换 5V/4A+ |
| 两端啸叫/发热 | SG90 脉宽超量程 | `SERVO_PULSE_MAX_US` 2500→2400 |
| `ERR POSITION_UNKNOWN` | 冷启动直接用 LINE/REPEAT_LINE | 先发 `POINT 0 0 0 300` 建立当前位置 |
| `ERR WORKSPACE` / `ERR IK` | 目标超工作空间/无解 | 参数控制在 x/y∈[-100,100]、z∈[-100,100] |

## 6. 与 v1 的差异提醒

- 设备名 `CDR01v2`（不是 `CDR01`），UUID 全新；旧上位机**无法连接**（预期）。
- 无 WiFi/UDP；`WIFI_*`/`HOSTNAME_*` 命令已移除（会回 `ERR INVALID_COMMAND`）。
- 串口调试仍支持文本命令与 `L:`/`R:` 前缀；BLE 用二进制帧（SIDE 字段）。
