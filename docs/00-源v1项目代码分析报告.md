### 1.2 固件构建系统

- **Arduino 工程**：主文件 `cdr01_firmware.ino` 仅 28 行，真正的逻辑全部在 `DeltaRobotController.{h,cpp}`（2393 行）和 `DeltaCommandParser.{h,cpp}`（382 行）中。
- 依赖库：**M5Unified**、**M5AtomicMotion**、**FastLED**、ESP32 Arduino core（BLE/WiFi/Preferences 为 core 自带）。
- 目标板：Arduino IDE 中选 M5Stack Atom/AtomS3 系列。
- 版本号机制：主 .ino 文件名 `cdr01_v0.4.0.ino` 的 `_v...` 后缀被解析为固件版本（`VERSION` 命令返回 `0.4.0`）。

### 1.3 原 "atmo" 开发板硬件

| 项 | 内容 |
| --- | --- |
| 主控 | **M5Stack ATOMS3 Lite**（ESP32-S3，8MB Flash，无 PSRAM）。固件同时兼容 Atom Lite/Matrix/Echo（ESP32-PICO）与 AtomS3 全系列 |
| 舵机驱动 | **ATOMIC Motion Base v1.2** 拓展底座：内置 STM32 协处理器 + I2C 舵机驱动（4 路 16 位 PWM，S1~S4）+ **INA226** 电流/电压计 + 18350 电池充放电路 + 电源开关 |
| 与主控连接 | I2C @100kHz；Atom 系列 SDA=25/SCL=21，AtomS3 系列 SDA=38/SCL=39（代码按板型自动选择） |
| 舵机 | FEETECH **FS90** ×6（但每台本体只用 3 个，见 §3.1） |
| 其他外设 | WS2811 LED ×1（GPIO35）、按键（M5.BtnA）、振动电机（GPIO8 PWM）、INA226 电池检测 |

**关键结论**：原版不存在 PCA9685，也没有"直驱 GPIO PWM"——舵机 PWM 由拓展底座的 STM32 协处理器产生，主控只发 I2C 命令 `setServoPulse(channel, pulse_us)`。因此移植到 ESP32-S3 直驱时，**只需用 LEDC 复刻"3 个逻辑通道的 µs 脉宽输出"这一行为即可**，协议与运动学完全不受影响。

## 2. 上位机通信协议（物理层 + 帧格式 + 指令集 + 状态回传）

### 2.1 三种物理通道

| 通道 | 参数 | 用途 |
| --- | --- | --- |
| **BLE**（上位机主通道） | 广播名 `CDR01`；Service `f060699b-7f92-4e28-83a1-aaeb6d456fc4`；Characteristic `30e2781e-b310-469f-8f93-2542aedef202`（READ+WRITE+NOTIFY）；另附标准电池服务 `0x180F`/特征 `0x2A19`（READ+NOTIFY） | cdr-player / cdr-scripter / web-tools / wifi-setup-tool 全部走这里 |
| **USB 串口** | 115200 bps，按行（`\n`）收命令；响应与回显也走串口 | 调试、Arduino 串口监视器 |
| **Wi-Fi UDP** | STA 模式，UDP 端口 **8000**，只收 T-Code 文本；mDNS 注册 `<hostname>.local` + 服务 `_tcode._udp`（默认 hostname `cdr01`） | MultiFunPlayer 等第三方 T-Code 软件 |

### 2.2 帧格式（固件视角）

- **无二进制帧**：所有命令都是**单行 ASCII 文本**。串口以 `\n` 分行；**BLE 每次 write = 一条完整命令**（上位机均不加换行符，最长可到 ~512 字符）；UDP 包内可含多行（按 `\n` 拆分逐行处理，带不带换行均可）。
- 命令前导/尾随空白会被 `trim()`。
- 响应格式（串口**总是**输出；BLE 侧写入特征值并 notify）：
  - 成功：`OK <message>`，例 `OK POINT started`
  - 失败：`ERR <code> <message>`，例 `ERR WORKSPACE Target out of workspace. Command ignored.`
  - 键值：`VALUE <key> <value>`，例 `VALUE battery voltage=4.10,current=0.05,level=93`
  - T-Code 设备命令原样回：`CDR01 firmware 0.4.0` / `TCode v0.3` / `OK DSTOP`
- **BLE 特征值永远保存"最近一次响应"**：wifi-setup-tool 依赖"write 后等 0.2s 再 read 同一特征"来取响应（notify 是可选加分项，read 是必需项）。

### 2.3 自定义指令集（完整指令表）

解析规则（`DeltaCommandParser.cpp`）：命令名大小写敏感、以首 token 识别；浮点参数用 `sscanf` 解析。

| `LINE x y z ms` | 4 | 当前直交坐标 → 目标，**笛卡尔直线插值**；当前位置未知则 `ERR POSITION_UNKNOWN` |

| `CIRCLE3D cx cy cz nx ny nz r ms` | 8 | 任意法线平面圆 1 周 |
| `LISSAJOUS cx cy cz ax ay az fx fy fz py pz ms` | 12 | 利萨茹曲线 1 周期（X 相位固定 0） |
| `ROSE cx cy cz r petals ms` | 6 | XY 平面玫瑰线 1 周期 |

### 2.4 T-Code v0.3 子协议（BLE/串口/UDP 通用）

- 行内空格分隔多 token；轴 token = 字母+1 位数字（`L0..L9`、`V0..V9`、任意 `A0..Z9` 可解析）。
- 值 = 轴号后连续数字当**小数部**：`L099` = 0.99（0~0.9999 钳位）。
- 修饰：`I毫秒`（到达时间）、`S速度`（T-Code 语义 0.xx/100ms，内部换算 `/sec`）。
- 默认轴映射（可改可存）：`L0→X`、`L1→Z`、`L2→Y`，范围 -100..100，不反相。
- `V0..V9` → 振动（多值取最大）；`R0..R9` 仅解析不动作；`D0/D1/D2` 回设备信息/TCode 版本/能力；`DSTOP` 急停；`$` 保存类 token 回 `OK`。
- **T-Code 为"实时跟随"模式**：收到即从当前点向目标点做直线插值（默认 50ms），**连续 750ms 收不到就停止运动并把振动归 0**（安全超时）。
- 未映射的轴 token 被忽略 → 支持两台设备用 L0-L2/L3-L5/L6-L8 分轴。

### 2.5 上位机四件套的行为差异（兼容性关键）

| 上位机 | 发送方式 | 是否读响应 | 关键兼容要求 |
| --- | --- | --- | --- |
| cdr-player | BLE 单次 write=1 条命令，无终止符，100ms/侧节流，**不读任何响应、不订阅命令 notify** | ❌ | 广播名精确 `CDR01`；特征可写；**MTU 需足够大**（它从不协商 MTU，Windows 默认 23 字节，而 `CIRCLE 0 0 0 50 3000` 已 22 字节）；BLE 地址需稳定；可双连接 |
| cdr-scripter | 同上；事件密集时 <10ms 间隔连发；pause/切轨发 `STOP` | ❌ | 固件必须**非阻塞收命令**；新命令抢占当前动作；`STOP` 随时可发 |
| web-tools | 同上 + write 后 read 记日志；CSV 调度器 50ms tick | 仅记录 | 支持不带响应写；长命令（REPEAT_LISSAJOUS ~50+ 字节）需要 Long Write/大 MTU |
| wifi-setup-tool | write(带响应)→等 0.2s→read 同一特征；notify 可选 | ✅ 必需 | **特征 read 必须返回最新响应**；`WIFI_STATUS` 必须回 `VALUE wifi connected[,ssid,ip,...]`（按此轮询 20s）；`WIFI_SAVE` 非阻塞 |

- **没有任何上位机会发送 `VERSION`**（只有 wifi-setup-tool 的手工命令框可能发）。
- 所有上位机都按**广播名精确等于 `CDR01`** 过滤设备；断线都不自动重连 → 固件必须在断开后重新开始广播。
- 上位机全部"发完即走"，固件**绝不能等待 ACK/握手**。

## 3. 6 个舵机：逻辑编号、左右侧对应（重要结论）

### 3.1 原版真实拓扑：2 台独立设备，左右分别控制

- BOM 与装配指南明确：CDR01 成品 = **左右两台完全独立的设备**，各含 1 个 ATOMS3 Lite + 1 个 ATOMIC Motion + **3 个 FS90**，两台用腰带连接。
- **每台固件只驱动 3 个逻辑通道**（`currentAngles[3]`，`setServoAngle(channel=0..2)`）：delta 三角臂本来就是 3 个自由度。左右两台各烧同一份固件、各自独立广播 `CDR01`、**各自独立接收命令**：
  - cdr-player / cdr-scripter 有左右两个槽位，CSV 的左右两列分别发往两台设备；
  - 两台靠 hostname（`cdr01-left/right`）区分；MultiFunPlayer 场景下左机改配 L3-L5、右机改配 L6-L8 实现分轴独立，或两台都保持默认 L0-L2 实现同轴镜像。
- 通道 0/1/2 ↔ Motion Base 的 S1/S2/S3 插座；装配指南注明"插错只会改变运动方向，无大碍"。
- 因此原版的能力是 **6 个舵机（= 3 通道 × 2 台）完全独立控制**，"同轴镜像"只是双台都保留默认映射时的一种用法。

### 3.2 单板 6 舵机拓扑的对应关系（修正后的方案）

ESP32-S3 单板接管全部 6 个舵机，固件按 **6 个逻辑通道 + 左右两个独立 delta 实例**实现，
忠实还原原版"左右分别控制"的能力：

| 逻辑通道 | 等价原版 | GPIO | 逻辑通道 | 等价原版 | GPIO |
| --- | --- | --- | --- | --- | --- |
| L0 | 左机 S1 | 4 | R0 | 右机 S1 | 16 |
| L1 | 左机 S2 | 5 | R1 | 右机 S2 | 17 |
| L2 | 左机 S3 | 15 | R2 | 右机 S3 | 18 |

每侧拥有独立的状态与运动引擎（当前位置、IK/FK、REPEAT/随机、T-Code Live 互不干扰）。
命令路由提供三条路径（详见《02》§5.4）：
1. 无前缀命令 → 双侧同步执行（默认，兼容原版单槽位/同轴用法）；
2. 扩展前缀 `L:` / `R:` → 只驱动对应一侧（串口/自定义工具精确控制）；
3. `BLE_DUAL_SLOT_MODE=true` → 第 1 路 BLE 连接=左侧、第 2 路=右侧（原版双槽位 App 的直接复刻；
   注意同一台 PC 对同一外设双连接在部分系统上受限）。
T-Code 轴槽位扩展为 6 个（0-2 左 / 3-5 右），默认两侧同为 L0-L2（镜像），右侧改配 L3-L5 即分轴独立。

### 3.3 角度范围与 PWM 脉宽

| 项 | 原版值 | 移植建议 |
| --- | --- | --- |
| 舵机角度域 | 0~180°（`setServoAngle` 内 `constrain`） | 同左，另加可配置软限位 |
| 脉宽换算 | `pulse = 500 + angle/180 × 2000` → **500~2500 µs** | SG90 标称 500~2400 µs：保留原公式与上下限，`config.h` 可调 |
| 信号频率 | 20ms 周期（50Hz，Motion Base 内部） | LEDC 50Hz |
| 中位 | 90° = 1500µs | 上电自检用 |
| 实际工作角度 | IK 解出的角度约 40°~140°（由臂长/工作空间决定），不会到物理极限 | — |

### 3.4 建议 GPIO 映射表（详细理由见《02-移植方案》）

| 逻辑通道 | 等价原版 | GPIO |
| --- | --- | --- |
| L0（左机 S1） | 左臂 0 | 4 |
| L1（左机 S2） | 左臂 1 | 5 |
| L2（左机 S3） | 左臂 2 | 15 |
| R0（右机 S1） | 右臂 0 | 16 |
| R1（右机 S2） | 右臂 1 | 17 |

每侧内部按同样规则把臂接到对应通道；若某通道方向反了，翻转 `SERVO_INVERT` 对应位。

## 4. Delta 运动学 / 插值 / 动作序列

### 4.1 几何常量（必须保持原值）

| 常量 | 值 | 含义 |
| --- | ---: | --- |
| baseRadius | 26.0 | 底座臂轴分布圆半径 |
| bicepLength | 25.0 | 主动臂长 |
| forearmLength | 40.0 | 从动臂长 |
| effectorRadius | 16.0 | 末端平台半径 |
| homeX/Y/Z | 0 / 0 / **-33** | Home 点（Z 负=下方） |
| workspaceRadius / workspaceHeight | 20.0 / 15.0 | 工作空间圆柱半径/半高 |

坐标换算：`x_act = 0 + x%/100 × 20`；`y_act = y%/100 × 20`；`z_act = -33 + z%/100 × 15`；`r_act = r%/100 × 20`。

### 4.2 逆运动学（IK）与正运动学（FK）

- **IK**（`delta_calcAngleYZ` 经典公式）：对每个臂把目标绕 Z 轴旋转到臂平面（0°/±120°），解 `(x,y,z)` 交点得 θ，`servoAngle = 90 - θ`。任一臂无解 → `ERR IK`。
- **FK**（球面三交点解析解）：把 `JOINT` 目标角换算回直交坐标；在工作空间内则更新"当前位置"，使 `JOINT` 后可直接 `LINE`。
- 工作空间判定：`√(dx²+dy²) ≤ 20.1 且 |dz| ≤ 15.1`（含 0.1 余量）。

### 4.3 执行模型（10ms 定时 tick）

- 硬件定时器 10ms 置位 `interruptFlag`，主循环消费；`steps = max(1, motion_ms/10)`。
- 运动模式：`Idle / JointInterpolation（关节插值）/ CartesianLine（笛卡尔直线）/ Approach（进轨接近段）/ Trajectory（圆/曲线采样）/ TCodeLive（T-Code 跟随）/ Wait（重复动作等待）`。
- **每 10ms**：直线/轨迹模式逐点算 IK 再写舵机（笛卡尔运动天然平滑）；关节模式每 tick 加固定步长角。
- **Approach 机制**：CIRCLE/REPEAT_* 等开始前，若当前位置距轨迹起点 >0.5mm，先以 `max(100, min(1000, motion_ms×15%))` ms 直线接驳到起点再入轨。**此行为必须复刻**，否则上位机脚本动作衔接会不一致。
- 完成回调：REPEAT_POINT/LINE/TRIANGLE 在 `handleCompletedMotion()` 里自续（翻转端点/顶点序号/等待时间），CIRCLE 类靠 `currentStep=0` 循环。
- **新命令抢占**：除 `BATTERY` 外，任何新命令先 `clearActiveMotion()` 再执行（上位机依赖这一点做动作切换与 STOP）。

### 4.4 轨迹类型

| 类型 | 参数化（t∈[0,1]） |
| --- | --- |
| CircleXY | 中心 + R·(cos2πt, sin2πt)；R<0 反向 |
| Circle3D | 法线正交基 u,v 上画圆 |
| Lissajous | 各轴 `A·sin(2πf·t + φ)`（φx=0，φy/φz 可配，度） |
| Rose | `r(t)=R·cos(petals·2πt)` 玫瑰线 |

开始前对 8 个采样点做工作空间+IK 预校验，不过则拒绝整条命令。

### 4.5 T-Code Live 跟随

收到 T-Code 直线轴 → 合并为直交目标 → 从当前点向目标直线插值（时间=I 指定或 S 换算或默认 50ms，钳位 10~5000ms）。连续 750ms 无新数据 → 停运动、振动归 0。当前位置未知时先以 home 初始化。

## 5. 内置随机动作（REPEAT_RANDOM 与按键）

- 启动时注册 4 条默认命令：`REPEAT_POINT 0 0 -50 0 0 50 1000`、`REPEAT_POINT 80 0 0 -80 0 0 1000`、`REPEAT_POINT 0 80 0 0 -80 0 1000`、`REPEAT_CIRCLE 0 0 0 75 2000`。
- 按键循环 4 态（每按一次）：**0 白灯**=JOINT 90 90 90 200（装配姿态）→ **1 青灯**=POINT 0 0 0 200（Home，使用姿态）→ **2 黄灯**=REPEAT_RANDOM 弱档（11 条预设）→ **3 紫灯**=REPEAT_RANDOM 强档（10 条预设）→ 循环。双击=回 90°。
- 弱/强预设表在 `DeltaRobotController.h:154-181`（移植时原样保留）。

## 8. 需要你确认的疑点清单（动手写固件前请过目，均有默认值、不阻塞）

1. **GPIO15/16 是 ESP32-S3 的 32K 晶体引脚**：绝大多数 N16R8 开发板没有焊 32kHz 晶振，15/16 可当普通 GPIO；请确认你的板子背面没有银白色小圆柱晶振（有则 15/16 不能用于舵机，需换 1/2/3/6/7/8/9/10/11/12/13/14/21/38/47/48 中的任意两个）。
2. **原版 LED 在 GPIO35，但 N16R8 的 33~37 被八线 PSRAM 占用**：状态 LED 必须换脚。默认用 GPIO2 当普通 LED（低有效/高有效可选），也支持外接 WS2812（建议 GPIO48，可配）。如果你板上有板载 RGB 灯，告诉我具体引脚。
3. **原版按键 = AtomS3 面板键（GPIO41）**：你的板子默认没有独立按键，默认禁用按键功能；可用 BOOT 键（GPIO0）替代（注意 GPIO0 是 strapping 脚，**上电时必须松开**，运行中按下没问题）。要启用请改 `config.h`。
4. **电池/INA226 不存在**：`BATTERY` 命令与 BLE 电池服务默认返回固定值（电压 5.0V、电流 0.1A、电量 100%），LED 不显示充放电态；可选 ADC 分压读真电压（`config.h` 配置分压比）。不影响任何上位机连接。
5. **左右侧是否镜像装配**：若某侧某臂装出来方向与期望相反，改 `config.h` 的 `SERVO_INVERT` 对应位（6 位，依次 L0 L1 L2 R0 R1 R2）即可，固件逻辑不用动。默认全部同向。
6. **SG90 与原版 FS90 的脉宽差异**：原公式 500~2500µs 覆盖 SG90 标称 500~2400µs；实际 IK 角度在 40°~140° 左右，不会碰到极端值。若你的 SG90 在两端有啸叫/抖动，把 `SERVO_PULSE_MIN/MAX` 收紧到 500/2400。
7. **单板 6 通道的左右独立控制方式（已按三路径实现）**：① 默认无前缀命令双侧同步（兼容原版单槽位/同轴用法）；② 扩展前缀 `L:`/`R:` 命令精确控制单侧（串口/自定义工具）；③ `BLE_DUAL_SLOT_MODE=true` 时第 1 路 BLE 连接=左侧、第 2 路=右侧，与原版"App 双槽位连两台 CDR01"一致——**但同一台 PC 对同一外设建双连接在部分系统（Windows bleak）上会失败**，此时请用 ② 或 T-Code 分轴（右侧槽位改配 L3-L5）。MultiFunPlayer 单 UDP 端点即可（默认 L0-L2 双侧镜像；右侧改配 L3-L5 后 L0-L5 分轴独立）。
8. **版本号**：固件默认回 `CDR01 firmware 0.4.0`（与原作者最新版一致，避免个别 App 做版本比较时异常），可在 `config.h` 修改。
9. **振动电机 GPIO8**：原版接 AtomS3 的 GPIO8；你的板子 GPIO8 空闲可直用。没有振动电机时该引脚输出 PWM 无副作用，`VIBRATE` 命令照常回 OK。
10. **BLE MTU**：上位机从不协商 MTU（Windows 默认 23 字节会导致 22 字节的测试命令写失败）。固件侧把 MTU 默认设为 517 并在服务端发起/接受交换，即可覆盖全部上位机（详见移植方案 §3.4）。
