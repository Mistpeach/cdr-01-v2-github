# CDR01 移植固件联调与排障手册（第 4 步交付物）

> 适用工程：`esp32s3-cdr01-firmware/`（PlatformIO）。配套《02-移植方案与接线映射.md》。
> 所有串口命令走 115200 bps；所有响应同时出现在串口与 BLE 特征值中。

---

## 1. 烧录步骤

### 1.1 PlatformIO（推荐，工程自带配置）

1. 安装 PlatformIO（VS Code 扩展或 `pip install platformio`）。
2. 用 VS Code 打开 `esp32s3-cdr01-firmware/` 目录。
3. 首次编译会自动下载 espressif32 平台与工具链（国内网络慢可设置镜像，见 1.4）。
4. USB 连接开发板 → 点 PlatformIO 工具栏 **Upload**（或 CLI `pio run -t upload`）。
5. 打开串口监视器（115200）验证启动日志：

```
[SELF TEST] Servo LEDC ready: 6ch @50Hz/16bit (3 logical x 2 sides)
Received Command: JOINT 90 90 90 200
Target Angles: 90.00 90.00 90.00
OK JOINT started
[SELF TEST] Firmware: CDR01 firmware 0.4.0
Setup complete
```

看到 `Setup complete` 即自检通过，6 个舵机已锁定 90°（1500µs）。

### 1.2 板型确认（重要）

`platformio.ini` 已按 **N16R8**（16MB Flash QIO + 8MB OPI PSRAM）配置。
- 若你的板子是 N8R8（四线 PSRAM）：`memory_type` 改 `qio_qspi`、`psram_type` 改 `qspi`。
- 烧录前确认板背**没有 32kHz 圆柱晶振**（影响 GPIO15/16，见 02 文档疑点 #1）。

### 1.3 Arduino IDE 方案（可选）

若坚持用 Arduino IDE：
1. 开发板选 `ESP32S3 Dev Module`；Flash 16MB、**OPI PSRAM**、USB CDC On Boot = Enabled、Upload 921600。
2. 把 `src/` 下所有 .cpp/.h 复制到同名 .ino 所在目录（Arduino 会一起编译），
   并把 `include/config.h` 放到 `src/` 里、在各文件顶部 `#include "config.h"`。
3. `main.cpp` 改名为同名 .ino。

### 1.4 PlatformIO 国内加速（实测有效方案）

PlatformIO 首次编译需下载约 1GB 工具链（esp32s3 还会强制下载 RISC-V 工具链用于 ULP 支持）。
国内直连 dl.registry.platformio.org 时 pio 自带的下载器**经常卡在 0%/半途**（本机实测）。
实测有效的方案：

**方案 A（推荐，本机验证过）：让 pio 走系统代理**

```powershell
# PowerShell 中设置代理后启动编译（示例为 Clash 默认端口 7897，改成你的端口）
$env:HTTP_PROXY="http://127.0.0.1:7897"
$env:HTTPS_PROXY="http://127.0.0.1:7897"
pio run
```

注意：pio 的 Python 下载器**不读 Windows 系统代理设置**，必须通过上面两个环境变量传入。
代理节点选好后实测下载速度 2~3MB/s，全程约 10 分钟。

**方案 B：手动预下载到 pio 缓存**（无代理环境）

pio 的包实际从 GitHub 镜像下载（HEAD 请求 302 重定向到
`github.com/ivankravets/pioreg-ci-mirror/releases/...`，响应头带 `x-pio-content-sha256`）。
可用任意下载工具（迅雷/aria2/浏览器）把文件放进 `%USERPROFILE%\.platformio\.cache\downloads\`，
**文件名 = SHA1(重定向后的URL + sha256值)**，pio 检测到缓存文件后会跳过下载直接解包。
所需四个包（Windows）：framework-arduinoespressif32(~235MB)、toolchain-xtensa-esp32s3(~81MB)、
toolchain-riscv32-esp(~247MB)、tool-esptoolpy(~0.5MB)。

## 2. 串口调试指令速查

串口监视器（115200，换行结尾）直接输入。**BLE 侧同样命令，一条 write = 一条命令，无换行。**

| 目的 | 命令 | 期望响应 |
| --- | --- | --- |
| 版本 | `VERSION` | `VALUE version CDR01 firmware 0.4.0` |
| 回中（装配姿态） | `JOINT 90 90 90 200` | `[L] OK JOINT started` + `[R] OK JOINT started` |
| Home 点 | `POINT 0 0 0 300` | `[L] OK POINT started` + `[R] OK POINT started` |
| 上位机测试命令 | `CIRCLE 0 0 0 50 3000` | `[L] OK CIRCLE started` + `[R] OK CIRCLE started` |
| 直线插值 | `LINE 0 0 -60 800` | 同上双侧 |
| 往复 | `REPEAT_LINE -50 0 -25 50 0 -25 700` | 同上双侧 |
| 三角形周回 | `REPEAT_TRIANGLE -50 0 -25 0 50 -10 50 0 -25 700` | 同上双侧 |
| 内置随机（弱） | `REPEAT_RANDOM` | `[L] OK REPEAT_RANDOM started` + `[R] ...` |
| 急停（双侧） | `STOP` | `OK STOP` |
| **仅左侧执行** | `L:POINT 100 0 0 300` | `[L] OK POINT started` |
| **仅右侧执行** | `R:POINT -100 0 0 300` | `[R] OK POINT started` |
| 单侧急停 | `L:STOP` / `R:STOP` | `OK [L] STOP` / `OK [R] STOP` |
| 电量 | `BATTERY` | `VALUE battery voltage=5.00,current=0.10,level=100` |
| 振动测试 | `VIBRATE 60` → `VIBRATE 0` | `OK VIBRATE set` |
| LED 状态 | `LED_STATUS` | `VALUE led reason=...,mode=auto,...` |
| T-Code 设备信息 | `D0` / `D1` / `D2` | 设备信息 / `TCode v0.3` / 6 轴能力（L0 L1 L2 L0 L1 L2 V0） |
| T-Code 跟随（默认镜像） | `L050 L125 L275I500` | 无响应（正常），两侧 XYZ 联动 |
| T-Code 分轴（独立控制） | `L050 L125 L275 L350 L475 L575` | 无响应，左=L0-L2、右=L3-L5（先按 §4.6 配置右侧槽位） |
| T-Code 急停 | `DSTOP` | `OK DSTOP` |
| Wi-Fi 状态 | `WIFI_STATUS` | `VALUE wifi disabled,...` 或 `connected,...` |
| Wi-Fi 配置 | `WIFI_SAVE myssid mypass` | `OK WIFI saved and connecting` |
| 主机名 | `HOSTNAME_SAVE cdr01-left` | `OK HOSTNAME saved` |
| T-Code 轴映射 | `TCODE_STATUS` | `VALUE tcode 0:L0=X:norm:-100.0..100.0 ... 5:L2=Y:norm:...`（6 槽位：0-2 左，3-5 右） |
| T-Code 轴保存 | `TCODE_SAVE` | `OK TCODE settings saved` |

调试常用组合：

```text
JOINT 90 90 90 200          # 双侧回中
POINT 0 0 0 300             # 双侧到 Home（约 66°）
L:POINT 100 0 0 300         # 仅左侧 X 最右
R:POINT -100 0 0 300        # 仅右侧 X 最左（与左侧成"剪刀"动作）
CIRCLE 0 0 -50 75 3000      # 双侧画大圆
L:CIRCLE 0 0 -50 75 3000    # 仅左侧画圆
REPEAT_ROSE 0 0 -25 50 4 2500   # 双侧玫瑰线
```

> 响应说明：无前缀命令由两侧引擎各执行一次，响应带 `[L]`/`[R]` 标签；
> `STOP`/`VERSION`/`BATTERY` 等全局命令不带标签。BLE 特征值始终保存最近一次响应。

## 3. 每个舵机单独测试

### 3.1 固件内逐通道测试（无需重烧）

固件有 **6 个独立逻辑通道**（L0 L1 L2 = GPIO4/5/15，R0 R1 R2 = GPIO16/17/18）。
用 `L:`/`R:` 前缀 + `JOINT` 只动一个角度即可单独验证任意一个舵机：

```text
JOINT 90 90 90 200        # 双侧回中
L:JOINT 60 90 90 400      # 仅左侧臂0（L0，GPIO4）动
L:JOINT 90 60 90 400      # 仅左侧臂1（L1，GPIO5）动
L:JOINT 90 90 60 400      # 仅左侧臂2（L2，GPIO15）动
R:JOINT 60 90 90 400      # 仅右侧臂0（R0，GPIO16）动
R:JOINT 90 60 90 400      # 仅右侧臂1（R1，GPIO17）动
R:JOINT 90 90 60 400      # 仅右侧臂2（R2，GPIO18）动
JOINT 120 120 120 400     # 双侧三臂同步外摆
JOINT 90 90 90 400        # 回中
```

判读：每条 `L:`/`R:` 命令应**只有一个舵机动**（串口响应带 `[L]`/`[R]` 标签）。
- 完全不动 → 该路信号线断/接错脚，或舵机坏。
- 动了但方向与期望相反 → `config.h` 的 `SERVO_INVERT` 对应位翻转（第 0..5 位 = L0 L1 L2 R0 R1 R2）。
- 动一下停住/抖 → 供电不足或该舵机损坏（见 §6 排查表）。

### 3.2 独立扫摆固件（重烧验证单舵机）

把下面片段替换 `src/main.cpp`（PlatformIO）或另开 Arduino 工程，逐脚验证：

```cpp
#include <Arduino.h>
#define PIN 4   // 依次改成 4/5/15/16/17/18
void writeAngle(float a) {
  if (a < 0) a = 0; if (a > 180) a = 180;
  int pulse = 500 + (int)(a / 180.0f * 2000.0f);        // 与原版公式一致
  uint32_t duty = (uint32_t)pulse * 65536UL / 20000UL;  // 50Hz/16bit
  ledcWrite(PIN, duty);
}
void setup() {
  Serial.begin(115200);
  Serial.printf("Servo test on GPIO%d\n", PIN);
  ledcAttach(PIN, 50, 16);
  for (int round = 0; round < 2; round++) {
    for (int a = 0; a <= 180; a += 2) { writeAngle(a); delay(15); }
    for (int a = 180; a >= 0; a -= 2) { writeAngle(a); delay(15); }
    Serial.printf("Round %d done\n", round + 1);
  }
  writeAngle(90);          // 锁定 90° 装摇臂
  Serial.println("Locked at 90deg / 1500us");
}
void loop() { delay(1000); }
```

> 注：你的测试固件用过 `544~2400µs` 与 14bit；本固件沿用原版 `500~2500µs`/16bit。
> 扫摆时若 SG90 在两端啸叫，把 `config.h` 的 `SERVO_PULSE_MAX_US` 收到 2400 再试。

## 4. 上位机 App 联调步骤

### 4.1 通用前置检查

- 上电后串口确认 `Setup complete`；BLE 广播名必须是 **`CDR01`**（手机/PC 扫描验证）。
- 一个上位机槽位只连本设备一次（本机 = 原版左右两台合并，连接一个槽位两侧即同步）。
- 先跑 `CIRCLE 0 0 0 50 3000`（web-tools/player 内置测试命令）验证链路。

### 4.2 CDR Player（Windows 媒体播放器）

1. 打开 cdr-player → 设备连接面板选一个槽位（Slot1 即可）→ 连接（按名字 `CDR01` 扫描）。
2. 播放器右侧动作测试按钮会发 `CIRCLE 0 0 0 50 3000`，观察舵机画圆。
3. 载入 CSV（`时间ms,左命令,右命令` 三列无表头；示例脚本在 `示例脚本csv/1.csv`）。
4. 播放模式与固件侧配合（见《02》§5.4 三种路由模式）：
   - **单槽位连接（最简单）**：播放器只连 Slot1，左列命令 → 固件默认双侧镜像执行；
     CSV 右列留空即可。
   - **双槽位独立控制**：`config.h` 打开 `BLE_DUAL_SLOT_MODE=true` 后，把 Slot1、Slot2
     **都连到本设备**（Slot1=左侧、Slot2=右侧，各接一路 BLE 连接）——与原版
     "两个槽位连两台 CDR01"行为完全一致。⚠️ 同一台 PC 对同一外设建 2 路连接
     在 Windows 上经常失败；失败时改用单槽位镜像，或换两台设备（如手机+PC）各连一路。
5. 暂停/停止：播放器发 `STOP`，固件双侧立即停并保持位置。
6. 播放器不读响应、不自动重连：掉线后需手动重新点连接（固件断开后会重新广播）。

### 4.3 CDR Web Tools（手机/浏览器 PWA）

1. 用 Chrome/Edge（支持 Web Bluetooth）打开 web-tools 页面。
2. 连接设备 → 选 `CDR01`。
3. Remote/Player 页：拖动滑杆发 POINT/自定义命令；播放 CSV 脚本（单设备 = 双侧镜像）。
4. Setup 页可配 Wi-Fi/T-Code 轴（命令同 wifi-setup-tool；轴面板的 slot 0-2 配置左侧）。
5. 注意：浏览器 BLE 写默认不带响应、MTU 由系统协商 —— 本固件 MTU 517，长命令（REPEAT_LISSAJOUS 等）可一次写入。

### 4.4 CDR Scripter（脚本编辑器）

1. 运行前端（Tauri/开发模式）+ 后端 sidecar（127.0.0.1:8765，Windows BLE）。
2. 连接：扫描 3s 按名 `CDR01`；单槽位 = 双侧镜像；双槽位独立控制同 4.2 第 4 条。
3. 编辑/播放脚本（CSV 三列）→ 固件非阻塞接收，动作密集时也能跟上。
4. Seek 跳转：>1200ms 会补发每侧最近一条命令 —— 固件对新命令抢占处理，行为正确。

### 4.5 CDR Wi-Fi Setup Tool（配 Wi-Fi 用）

1. 打开工具 → 设备连接（扫描按名 `CDR01`）。
2. Wi-Fi 面板：填 SSID/密码 → `WIFI_SAVE ssid pw`（**SSID 不能含空格**）→ 状态确认轮询 20s。
3. Hostname：`HOSTNAME_SAVE cdr01-left`（或任意 `a-z0-9-`）。
4. T-Code 轴面板只操作左侧槽位（0-2）；右侧槽位（3-5）用"任意命令"框发送，
   例：`TCODE_AXIS 3 L3 X 0 -100 100`（右侧改用 L3-L5 分轴独立，见 4.6）。
5. 工具依赖"写后 0.2s 读特征取响应"：本固件每次响应都会更新特征值，兼容 ✅。

### 4.6 MultiFunPlayer（UDP T-Code）

1. 先用 4.5 配好 Wi-Fi 并确认 `WIFI_STATUS` 回 `VALUE wifi connected,...`。
2. MultiFunPlayer 底部 `+` → **UDP** → 设置 Endpoint 为 `cdr01.local`（或开发板 IP），端口 8000。
3. 两种用法：
   - **双侧镜像（默认）**：Device 轴保持默认 TCode-0.3（L0/L1/L2），funscript 的
     L0-L2 同时驱动左右两侧——等价原版"两台设备都保持默认 L0-L2"。
   - **左右独立**：把右侧槽位改配成 L3-L5（依次发）：
     ```
     TCODE_AXIS 3 L3 X 0 -100 100
     TCODE_AXIS 4 L4 Z 0 -100 100
     TCODE_AXIS 5 L5 Y 0 -100 100
     TCODE_SAVE
     ```
     之后 L0-L2 只驱动左侧、L3-L5 只驱动右侧（等价原版 L3-L5/L6-L8 双机分轴）。
4. 播放带 funscript 的视频 → 固件走 T-Code Live：连续 750ms 收不到数据会自动停（安全超时）。
5. mDNS 解析不稳时直接用 IP（`WIFI_STATUS` 里看 ip=...）。

## 5. 安全行为说明（与原版对齐）

| 场景 | 行为 |
| --- | --- |
| `STOP` / `DSTOP` / 按键回中 | 立即停止、清 REPEAT/随机状态；舵机保持最后位置（不掉电） |
| T-Code 数据中断 750ms | 自动停运动、振动归 0 |
| 新命令到达 | 抢占当前动作（BATTERY 除外） |
| 目标超工作空间 / IK 无解 | 拒绝执行并回 `ERR WORKSPACE` / `ERR IK` |
| BLE 断开 | 默认继续动作（原版行为）；`config.h` 打开 `SAFETY_STOP_ON_BLE_DISCONNECT` 则急停 |
| 角度越界 | `SERVO_ANGLE_MIN/MAX` 软限位钳位（默认 0/180） |
| 堵转/过流 | 本板无电流采样，无堵转检测；靠限位+工作空间保护。**装机时确保机械不卡死** |

## 6. 常见问题排查表

| 现象 | 可能原因 | 排查/处理 |
| --- | --- | --- |
| 串口无输出 | USB CDC 未开 / 线坏 / 波特率错 | 确认 115200；确认 CDC On Boot；换 USB 线；长按 BOOT 重烧 |
| 舵机完全不动 | 信号接错 / 没共地 / 舵机没电 | 查信号线是否对应 GPIO 表；万用表量舵机端 5V；确认外部电源 GND 与板 GND 连通 |
| 舵机乱抖/抽动 | **未共地**（最常见）/ 电源不足 / 信号线过长 | 先查共地；给 1000µF 换更近位置；缩短信号线；换 3A+ 电源 |
| 一上电就"跳一下" | 正常现象（上电到 LEDC 稳定前的自由摆动） | 无需处理；约 0.5s 内回中锁定 |
| 动作剧烈时复位重启 | 5Vin 经板载二极管压降过大 / 电源功率不足 | 换 5V/4A+ 电源；把开发板供电改到母线直供；缩短电源线 |
| 某侧某臂方向与期望相反 | 该通道装配镜像 / 摇臂装反 | 改 `config.h` 的 `SERVO_INVERT` 对应位（0-5 位 = L0 L1 L2 R0 R1 R2）重烧（无需拆线） |
| 只有 5 个舵机动 | 单个信号线断路/接错脚 | 按 §3.1 逐通道定位；换舵机交叉验证 |
| 某个舵机只能动半程 | SG90 个体脉宽差异 | 微调该通道脉宽范围，或换舵机 |
| 两端啸叫/发热 | 脉宽超出该 SG90 量程 | `SERVO_PULSE_MAX_US` 2500→2400 |
| BLE 扫描不到 `CDR01` | 广播未起 / 被另一台占用 / 距离 | 串口确认 `BLE advertising started...`；靠近扫描；重启板子 |
| 上位机连接后命令无效 | 写的是旧固件特征 / 连接了原版设备 | 确认连的是本板 MAC；断开重连；用串口验证命令本身正常 |
| web-tools 长命令发不出去 | 浏览器 MTU 限制（本固件已 517，一般不是它） | 换 Chrome/Edge；分两次发短命令验证 |
| wifi-setup 提示状态永远 connecting | SSID/密码错 / 2.4G-only 路由 | 确认 2.4GHz；确认 SSID 无空格；看串口 WiFi 日志 |
| MultiFunPlayer 连不上 UDP | 未连 Wi-Fi / 端口错 / mDNS 解析失败 | `WIFI_STATUS` 确认 connected；Endpoint 改 IP；确认端口 8000 |
| T-Code 动一下就停 | 750ms 安全超时（正常） | 确认上位机持续发流；一次性测试用 `I500` 间隔参数 |
| `ERR POSITION_UNKNOWN` | 冷启动后直接用 LINE/REPEAT_LINE | 先发 `POINT 0 0 0 300`（或任意 POINT/JOINT）建立当前位置 |
| `ERR WORKSPACE` | 目标超出 ±20mm/±15mm 空间 | 参数控制在 x/y∈[-100,100]、z∈[-100,100] 且实际半径受限 |
| 固件报 `[SELF TEST] Servo LEDC init FAILED` | GPIO 被占用（如 15/16 接了 32k 晶振） | 换空闲脚（1/2/3/6/7/8/9/10/11/12/13/14/21/38/47/48）改 `config.h` |
| 动作比脚本慢半拍 | 上位机无 ACK、固件命令队列正常 | 属正常；脚本时间戳间隔 ≥50ms 效果最佳 |
