# CDR01 → ESP32-S3 N16R8 移植方案与接线映射表（第 2 步交付物）

> 配套《01-代码分析报告.md》。本方案严格遵循你给定的引脚（GPIO 4/5/15/16/17/18）与 5V 供电拓扑，未做任何更改；凡有风险处均以 ⚠️ 标注说明，不改你的决定。

---

## 1. 技术选型：Arduino-ESP32 + LEDC 直写（不用 ESP32Servo）

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| **Arduino-ESP32 core 3.x + LEDC 直写** | ✅ 采用 | ① 原版脉宽公式 `500+angle/180×2000 µs` 可**逐微秒复刻**，无中间层换算误差；② 无第三方库依赖，编译环境最稳；③ 你已验证过该板上 `ledcAttach` 直驱可行（测试固件 README）；④ ESP32-S3 有 8 路 LEDC 低功耗通道：6 路舵机共用 1 个 50Hz 定时器 + 振动电机 1 路 1kHz，共 7 通道 2 定时器，**余量足够** |
| ESP32Servo 库 | ❌ 不用 | 在 S3 上可用，但内部自管定时器/通道、对 6 舵机 50Hz 无增益；且默认 16 路通道分配在 core 3.x 与 WiFi/BLE 共处时偶有兼容问题；引入依赖反而不如直写可控 |
| PCA9685 外挂 | ❌ 不用 | 你已确定直驱引脚，且 LEDC 完全胜任 |

**LEDC 参数**：频率 50Hz（20ms 周期）、分辨率 16bit（0.305µs/步，与原版 Motion Base 的 16 位 PWM 精度相当）、`duty = pulse_us × 65536 / 20000`。

**core 版本兼容**：`platformio.ini` 锁定 `espressif32@6.9.0`（Arduino core 3.0.7，IDF 5.1.4）。`ledcAttach` 新旧 API 与振动电机 PWM 均已做 `ESP_ARDUINO_VERSION_MAJOR` 版本守卫（与原作者在振动电机上的写法一致）。

## 2. GPIO 复用与 strapping 核对（ESP32-S3）

| 引脚 | 用途 | 核对结论 |
| --- | --- | --- |
| GPIO 4 | 舵机 CH0-L | ✅ 无 strapping、无 Flash/PSRAM/USB 冲突；ADC1_CH3 但 PWM 输出不用 ADC |
| GPIO 5 | 舵机 CH1-L | ✅ 同上（ADC1_CH4） |
| GPIO 15 | 舵机 CH2-L | ⚠️ 32K 晶振脚 XTAL_32K_P。**绝大多数 N16R8 板未焊 32k 晶振，可用**；烧录前确认板背无小圆柱晶振 |
| GPIO 16 | 舵机 CH0-R | ⚠️ 32K 晶振脚 XTAL_32K_N，同上 |
| GPIO 17 | 舵机 CH1-R | ✅ 空闲（ADC2_CH6） |
| GPIO 18 | 舵机 CH2-R | ✅ 空闲（ADC2_CH7，USB 是 19/20 不冲突） |
| （默认）GPIO 8 | 振动电机 PWM | ✅ 空闲，1kHz/8bit |
| （默认）GPIO 2 | 状态 LED（普通 GPIO 模式） | ✅ 空闲，多数 S3 开发板此脚无板载占用 |
| （可选）GPIO 0 | 模式按键（BOOT 键） | ⚠️ strapping 脚：**上电瞬间必须松开**；运行中按下无害。默认禁用 |
| （可选）GPIO 48 | 外接 WS2812 状态灯 | ✅ 空闲 |
| （可选）GPIO 14 等 | 电池 ADC 分压输入 | 与你的测试固件一致，默认关闭 |

**结论**：4/5/17/18 完全无隐患；15/16 唯一风险是板载 32k 晶振（见疑点清单 #1）。ESP32-S3 的 strapping 只有 GPIO0/3/45/46，全部避开；Flash 占 26~32、八线 PSRAM 占 33~37，也全部避开。

## 3. 舵机接线映射表（最终版：6 个独立通道）

### 3.1 与原版拓扑的对应关系（重要）

原版成品 = **左右两台独立设备**（各 1 个 ATOMS3 Lite + Motion Base + 3 个 FS90），
各自广播 `CDR01`、**各自独立接收命令**——上位机（cdr-player/scripter 的左右双槽位、
CSV 左右两列、MultiFunPlayer 的 L3-L5/L6-L8 分轴）分别驱动左右两侧。

本板 = 一台 ESP32-S3 直驱全部 6 个舵机，因此固件把逻辑通道扩展为 **6 个**，
每侧一个完整独立的 delta 运动实例（左右各有自己的 IK/FK、当前位置、REPEAT/随机、
T-Code Live 状态，互不干扰）：

| 逻辑通道 | 等价原版 | 本板 GPIO | 三角臂位置（俯视，FK/IK 约定） |
| --- | --- | --- | --- |
| **L0** | 左机 S1 | **GPIO 4** | 臂 0：+Y 方向（装置"前方"） |
| **L1** | 左机 S2 | **GPIO 5** | 臂 1：绕 Z 逆时针 120° |
| **L2** | 左机 S3 | **GPIO 15** | 臂 2：绕 Z 逆时针 240° |
| **R0** | 右机 S1 | **GPIO 16** | 臂 0：+Y 方向 |
| **R1** | 右机 S2 | **GPIO 17** | 臂 1：120° |
| **R2** | 右机 S3 | **GPIO 18** | 臂 2：240° |

- 电源：所有舵机红线 → 外部 5V 正极；棕/黑线 → 外部 5V 负极；**信号线各自独立**。
- 若装完发现某通道方向反了：改 `include/config.h` 的 `SERVO_INVERT` 对应位（第 0..5 位
  依次 = L0 L1 L2 R0 R1 R2），无需改线。
- 装机顺序建议：先全部 `JOINT 90 90 90 200`（白灯姿态，1500µs）装摇臂至最接近水平，
  再按《03-联调与排障手册》逐通道验证。

### 3.2 `config.h` 中的表达方式

```c
#define SERVO_GPIO {4, 5, 15, 16, 17, 18}   // L0 L1 L2 | R0 R1 R2
#define SERVO_INVERT {false,false,false,false,false,false}
```

## 4. 供电与共地注意事项（按你给定的拓扑执行）

你的拓扑（5V 开关电源 → 1000µF → 板 5Vin + 舵机 VCC；负极 → 1000µF → 板 GND + 舵机 GND；每舵机并联 1µF）本身是正确做法，以下为执行要点：

1. **单点共地、星形供电**：从 1000µF 电容两脚引出电源母线，舵机电源**直接取自母线**，不要经由开发板 5Vin 转接（SG90 堵转瞬态电流可到 700mA+，6 只同时动作瞬时 3~4A，开发板 5Vin 走线与保险丝不是为大电流设计）。开发板 5Vin 只需一根单独支路。
2. **粗线优先**：电源母线建议 ≥0.5mm²（22AWG），信号线 26~28AWG 足够（高阻输入，电流 <1mA）。
3. **1000µF 位置**：焊在电源进线端/母线起点，物理上尽量靠近舵机群；每个舵机的 1µF 贴片**直接焊在舵机接线端子两端**（越近越好），抑制 PWM 换相噪声。
4. **信号回路**：ESP32 GND 与电源 GND 必须可靠相连（你的拓扑已含）。**不共地 = 舵机乱抖/不动**，是最常见故障（排障手册有对应条目）。
5. **地环路**：只保留"母线单点"这一条 GND 连接，舵机信号线地别走第二条回路；USB 数据线插着调试时 PC 地经 USB 接入是正常状态（同一点），不会形成环。
6. **上电顺序**：先开 5V 电源再插 USB，或同时——LEDC 在 50Hz 下持续输出，上电瞬间舵机短暂自由摆动属正常，`setup()` 会在 ~500ms 内回中锁定。
7. ⚠️ **唯一建议（不强制）**：若你的开发板 5Vin 经板载二极管/保险丝，长时间 6 舵机大动作时板端压降可能触发复位。若遇到"动作一剧烈就重启"，把开发板电源也改到母线直供（跳过 USB），这是后话，先在现有拓扑下试。

## 5. 通信协议兼容层设计

### 5.1 BLE（与所有上位机对齐）

| 项 | 值 |
| --- | --- |
| 广播名 | `CDR01`（**精确**，四个上位机都做 == 匹配） |
| Service UUID | `f060699b-7f92-4e28-83a1-aaeb6d456fc4` |
| 命令特征 UUID | `30e2781e-b310-469f-8f93-2542aedef202`，READ + WRITE + NOTIFY + **显式 CCCD(BLE2902)**（原版只在电池特征挂了 CCCD，本版主特征也挂上，notify 更稳） |
| 电池服务 | `0x180F` / `0x2A19`（READ+NOTIFY，uint8 0~100；连接期间每 30s notify 一次） |
| MTU | **默认 517**（`BLEDevice::setMTU(517)`），并支持中央发起的 MTU 交换——cdr-player 从不协商 MTU，Windows 默认 23 字节会卡死 22 字节的测试命令，这一项是兼容四件套的关键 |
| 断开处理 | 断开后自动重新广播（上位机都不自动重连，需用户手动重连） |
| 多连接 | ESP32 BLE 默认支持多连接，cdr-player/scripter 双槽位可同时连本机 |
| 写入语义 | 每次 write = 1 条命令（无终止符），与 Serial 共用同一命令处理入口；写带/不带响应都支持 |
| 响应 | 任何命令响应同步：Serial 输出 + 特征 value 更新（供 read）+ 已订阅则 notify |

### 5.2 串口

115200，`\n` 分行，非 T-Code 命令回显 `Received Command: ...`，响应与 BLE 同源。**与 USB-CDC 模式绑定**（`ARDUINO_USB_CDC_ON_BOOT=1`）。

### 5.3 Wi-Fi UDP（MultiFunPlayer 路径）

STA + UDP **8000** 只收 T-Code；mDNS `<hostname>.local` + `_tcode._udp`；默认 hostname `cdr01`；
`WIFI/WIFI_SAVE/WIFI_STATUS/WIFI_FORGET/WIFI_STOP` 全命令保留，Preferences 命名空间
`cdr01_wifi`/`cdr01_host` 与原版一致。**T-Code 轴槽位扩展到 6 个（槽位 0-2 = 左，3-5 = 右）**，
默认两侧都是 L0=X/L1=Z/L2=Y（一个 UDP 端点发 L0-L2 = 两侧镜像同步，与原版"两台设备默认同轴"一致）；
把右侧槽位改配成 L3/L4/L5（`TCODE_AXIS 3 L3 X 0 -100 100` 等）即可与原版一样分轴独立控制两侧。

### 5.4 指令集覆盖与左右路由

`DeltaCommandParser` 100% 原样移植（全部命令 + T-Code 解析规则）。命令路由新增三层机制
（**协议不变**，原版 App 发送的裸命令行为可控）：

| 模式 | 触发方式 | 行为 | 适用 |
| --- | --- | --- | --- |
| 双侧镜像（默认） | 任何无前缀命令 | 左右两个 delta 实例同步执行同一命令 | 原版 App 单槽位连接；原版"两台同轴"场景 |
| **侧前缀（扩展语法）** | `L:命令` / `R:命令` | 只发给对应一侧（`L:POINT 0 0 0 300`、`R:REPEAT_LINE ...`、`L:STOP`） | 串口/自定义工具精确单侧控制 |
| 双槽位模式（配置开关） | `BLE_DUAL_SLOT_MODE=true` 后第 1 路 BLE 连接=左侧、第 2 路=右侧 | 每路连接只驱动对应侧，与原版"App 两个槽位连两台 CDR01"完全一致 | 原版双槽位 App（cdr-player/scripter） |

⚠️ 双槽位模式的平台限制：同一台 PC 对同一 BLE 外设建立 2 路连接在部分系统上不被允许
（Windows bleak 实测常失败）；两台设备（如手机+PC）各连一路则可行。单 PC 双槽位场景若
受限，请用侧前缀命令或 T-Code 分轴（右侧改配 L3-L5）实现独立控制。

响应格式：全局命令响应保持 `OK ...`/`ERR ...`/`VALUE ...` 原样；来自两侧运动引擎的响应带
`[L]`/`[R]` 标签（如 `[L] OK POINT started`），便于串口调试分辨两侧。

## 6. 代码分层设计

```
esp32s3-cdr01-firmware/
├── platformio.ini            # 板型/Flash16MB/OPI PSRAM/USB-CDC/监控 115200
├── include/
│   └── config.h              # ★ 全部可调常量集中于此（中文注释）
└── src/
    ├── main.cpp              # setup/loop + 10ms tick（millis 调度）
    ├── DeltaCommandParser.h/.cpp   # 协议层：原样移植，零业务改动
    ├── DeltaRobot.h/.cpp           # 单侧 delta 运动引擎（左右各一实例，6 通道独立）
    ├── RobotController.h/.cpp      # 全局层：传输/全局命令/左右路由/LED/按键/电池
    ├── ServoHAL.h/.cpp             # 舵机 HAL：LEDC ×6 独立通道（50Hz/16bit）
    ├── StatusLed.h/.cpp            # 状态灯：普通 GPIO / WS2812(RMT) / 关闭
    ├── BatteryMonitor.h/.cpp       # 电量：固定值 / ADC 分压
    └── Vibrator.h/.cpp             # 振动电机：LEDC 1kHz（GPIO8）
```

| 层 | 职责 | 移植策略 |
| --- | --- | --- |
| 协议层（Parser） | 文本命令识别、参数解析、T-Code 解析 | 原样复制，附带原版权信息 |
| 传输层 | Serial 行处理 / BLE onWrite（含连接路由）/ UDP 分包 | 与原版同构；BLE 增加 MTU、CCCD 与双槽位路由 |
| 指令路由层 | 全局命令（VERSION/WIFI/HOSTNAME/TCODE_CONFIG/LED/BATTERY/STOP/VIBRATE）+ 左/右/双侧分发（`L:`/`R:` 前缀、双槽位模式） | **新写**（单板 6 通道的必然产物） |
| 动作引擎（×2） | 每侧独立：IK/FK、关节/直线/轨迹插值、Approach、REPEAT 状态机、T-Code Live、Wait、随机动作 | 原样移植（10ms 节拍改为 millis 调度，节拍值不变） |
| 舵机 HAL | 6 物理通道独立输出、脉宽换算、反相、软限位 | **新写**（替换 M5AtomicMotion） |
| 安全层 | 工作空间/IK 预校验、STOP/DSTOP、T-Code 750ms 超时、角度钳位、可选断线停机 | 原版逻辑保留 + 新增可选项（见下） |
| 状态层 | LED 状态机、按键、电池 | 原版逻辑保留，硬件抽象替换 |

**config.h 中的关键可调项（节选）**：6 舵机 GPIO/反相/脉宽范围/角度软限位、delta 几何常量
（默认与原版一致）、T-Code 超时/时间钳位、`BLE_DUAL_SLOT_MODE` 双槽位开关、BLE 名称/UUID、
Wi-Fi 编译期默认凭据、振动/按键/LED/电池引脚与模式、固件版本号。

## 7. 与原代码的差异清单

### 7.1 必须改的（硬件差异）

| # | 差异 | 原版 | 本移植 |
| --- | --- | --- | --- |
| 1 | 舵机驱动 | M5AtomicMotion I2C 协处理器 | LEDC 6 通道直驱（50Hz/16bit，脉宽公式不变） |
| 2 | 舵机拓扑 | 2 台设备 × 3 通道（左右独立设备） | 1 台设备 × **6 逻辑通道**（L0-L2/R0-R2，每侧独立 delta 实例） |
| 3 | 左右控制方式 | 两台 CDR01 双槽位/双 UDP 端点 | 镜像默认 + `L:`/`R:` 前缀 + BLE 双槽位模式（config 开关）+ T-Code 6 轴槽位 |
| 4 | 状态 LED 引脚 | GPIO35（N16R8 上被 PSRAM 占用） | 默认 GPIO2 普通 LED；可配 WS2812@GPIO48 或关闭 |
| 5 | 按键 | M5.BtnA（GPIO41） | 默认禁用；可选 GPIO0（BOOT）/任意脚，自写消抖与双击检测（作用于两侧） |
| 6 | 电池检测 | INA226（每台一个） | 默认固定值（5V/100%）；可选 ADC 分压 |
| 7 | 振动电机 | 每台一个 | 单板共享一个输出（GPIO8），两侧 VIBRATE 指向同一电机 |
| 8 | 10ms 节拍 | 硬件定时器中断置位 | `millis()` 轮询（节拍值、步进数学完全不变） |
| 9 | BLE 细节 | 主特征未显式挂 CCCD；未设 MTU | 主特征显式 BLE2902；`setMTU(517)`；写入事件按 conn_id 路由 |
| 10 | T-Code 轴槽位 | 每台 3 槽位 | 6 槽位（0-2 左 / 3-5 右），默认两侧同为 L0-L2；D2 能力回 6 轴 |
| 11 | 启动自检 | 连不上 Motion Base 则死循环 | LEDC 通道申请检查 + 双侧回中 + 日志（不阻塞启动） |

### 7.2 保持不变的（协议/行为）

- 广播名、双 UUID、电池服务、命令文本格式与全部指令集、OK/ERR/VALUE 响应格式。
- delta 几何常量、IK/FK 公式、工作空间判定、百分比坐标换算。
- 插值/Approach/REPEAT 状态机/T-Code Live/750ms 超时/新命令抢占语义。
- `REPEAT_RANDOM` 弱/强预设命令表、按键 4 态行为（启用按键时）。
- Preferences 三个命名空间与键名。
- 脉宽公式 `500 + angle/180×2000`（上下限入 config 可调，默认原值）。

### 7.3 新增（安全增强，均有开关、默认不改变原版行为）

| 新增项 | 默认 | 说明 |
| --- | --- | --- |
| `SERVO_ANGLE_MIN/MAX` 软限位 | 0/180（=原版） | 可收紧到 10/170 等 |
| `SERVO_PULSE_MIN/MAX` | 500/2500（=原版） | SG90 可收紧到 500/2400 |
| `SAFETY_STOP_ON_BLE_DISCONNECT` | false（=原版：断线继续动作，便于单机使用） | 置 true 则 BLE 断开即急停，远程操控更安全 |
| 上电自检日志 | 新增 | `[SELF TEST] ...` 串口输出 LEDC 申请结果与回中确认 |
